# weixin-decryptor-for-new-weixin

针对**新版微信（4.1.11+）**数据库密钥方案变更的工具与文档。

> ⚠️ **先读这一节，避免误期待**
>
> 本仓库**没有**提供可用的完整密钥提取器。
> 提供的是：**回归诊断**、**FTS 兜底方案**（已实测可用）、**静态偏移推导工具**（半成品）。
> 详见下方[能力矩阵](#能力矩阵)。

## 背景

社区工具 `wechat-decrypt` 通过扫描微信进程内存中的
`x'<64hex_enc_key><32hex_salt>'` 模式提取数据库密钥。该方案在
**微信 4.1.11+ 已完全失效**，且原项目 `ylytdeng/wechat-decrypt`
已于 2026-07-13 被 DMCA 下架。

失效的**实际后果**比"不能用"更糟：解密流程不报错，但会**静默跳过**拿不到
密钥的新消息分片，导致导出的记录**丢掉最近的全部消息**而使用者毫无察觉。

## 能力矩阵

| 能力 | 状态 | 说明 |
|---|---|---|
| 内存扫描取密钥 | ❌ 失效 | 机制已变，不可修复 |
| FTS 兜底补消息 | ✅ **已实测** | 在 4.1.13.65 上验证，817/917 锚点命中 |
| 新旧分片密钥缓存刷新 | 📋 已定位 | 设计缺陷，需 upstream 改 `main.py` |
| codec 偏移静态推导 | ⚠️ 半成品 | 能推出候选偏移，**但未经运行时验证** |
| 完整密钥提取（Frida） | ❌ 未提供 | 需 Frida spawn + 处理 anti-hook，见下 |

## 快速开始

### FTS 兜底：把丢掉的消息找回来

如果你的导出结果缺了最近的消息（尤其是微信更新过之后）：

```bash
# 预览，不覆盖原文件
python tools/recover_fts.py --decrypted-dir <解密目录> --messages data/messages.json

# 确认无误后就地更新
python tools/recover_fts.py --decrypted-dir <解密目录> --messages data/messages.json --in-place
```

### 诊断当前的密钥状态

```bash
python tools/find_wechat_codec_offset.py [Weixin.dll 路径]
```

未指定路径时自动在常见安装目录下按版本号找最新的 `Weixin.dll`。

输出示例：

```
[*] 微信版本: 4.1.13.65
[*] MMV1 字符串 VA: ['0x189242d48']
[+] 引用点(disp32) RVA 0x3634F4C
[+] 所属函数       RVA 0x3634F10 .. 0x3634F92  (130 字节)
[+] hook 偏移      Weixin.dll + 0x3634F10
```

## 新机制是什么

```
password ≠ enc_key

enc_key = PBKDF2-HMAC-SHA512(password, salt, 256000, 32)
salt    = 数据库文件头前 16 字节
```

内存中保存的是 **password**（KDF 的输入），不是可直接使用的 `enc_key`。
所以"在内存里搜 enc_key"这条老路从根上就不通了。

获取 password 需要 **Frida spawn 早期注入**（attach 会错过），
且该路径**存在 anti-hook 检测**。

### 一个重要且容易被误解的点

失效的**不是密钥，是提取方法**。实测：18 个数据库中 17 个的 `salt` 自
2026-06 以来一字未变，其旧密钥至今仍能通过 HMAC 校验 —— 即
`password` **长期稳定**，微信并没有"轮换密钥"。

新出现的分片（`message_1.db` 等）之所以打不开，只是因为它是**新文件**、
有**新 salt**、因而有**新派生密钥** —— 这是正常建库行为。

> 所以不存在「每次微信更新都要重新对抗」的军备竞赛。
> 只要能拿到那个长期稳定的 `password` + 任意文件的 `salt`，
> 就能派生出该文件（含所有新分片）的 `enc_key`。

## 关于「静态偏移推导」这个半成品

社区方案把 hook 目标函数的偏移**硬编码**（例如 4.1.12.26 的 `0x3486140`），
微信每次更新都会失效——这正是本次踩坑的直接原因。

`tools/find_wechat_codec_offset.py` 改为**静态推导**：

1. 在 `Weixin.dll` 里定位 `MMV1` 魔数字符串，算出 VA
2. 扫描 `.text` 中 RIP-relative 引用该字符串的指令
3. 用 `.pdata`（x64 异常表）反查该指令所属函数的起始 RVA

换版本重跑即可，不需要人工逆向。

**但请注意**：推出的是**候选**偏移，尚未经运行时验证。在 4.1.13.65 上，
候选函数只有 130 字节、内容是加载魔数字符串后比较，**更像是日志/断言助手**，
不像接收 password 的配置入口。欢迎验证或修正。
